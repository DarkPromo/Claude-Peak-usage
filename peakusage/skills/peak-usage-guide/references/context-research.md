# When Claude benefits from a fresh context

Claude’s advertised context window tells you how much it can hold. How much it can use reliably depends on the model, the task, where important evidence appears, and what else is in the conversation. Claude 3.5 Sonnet showed a measurable decline by 4,000 tokens on one difficult retrieval test. Claude Opus 4.8 performed much better at 256,000 tokens than at one million on a graph reasoning test. More recent Claude models have completed substantial coding work in episodes that reach one million tokens. Peak Usage starts with a configurable **65% soft threshold, a 160,000-token cap on that threshold, and an 85% hard threshold**. These values set when to consider a handoff and reserve room to prepare it. They are engineering defaults to test against your workload. [NoLiMa](https://proceedings.mlr.press/v267/modarressi25a.html), [Opus 4.8 system card](https://www-cdn.anthropic.com/0f0c97ad20d8005706296bd92aa1c27c6b2f4f61/Claude%20Opus%204.8%20System%20Card.pdf), [Sonnet 5.5 system card](https://assets.claude.com/870c8f525702625d2c62fc6dd04c857e3250bec1.pdf)

## Different tasks lose quality at different lengths

| Test | Measured result | How to read it |
|---|---|---|
| Semantic retrieval, NoLiMa (ICML 2025) | Claude 3.5 Sonnet scored **87.5%** on the short-context baseline, **77.6%** at 4K, **61.7%** at 8K, **45.7%** at 16K, and **29.8%** at 32K. Its advertised context was 200K. | Questions and evidence had little lexical overlap. The authors call 4K the effective length because it was the last tested length at which this model retained at least 85% of its baseline. This finding applies to an older model on this task. [NoLiMa, Table 3](https://proceedings.mlr.press/v267/modarressi25a.html) |
| Conversational recall, Chroma Context Rot (2025) | On 306 selected LongMemEval questions, focused prompts averaged **about 300 tokens**, and the full conversations averaged **about 113K**. Claude models showed the largest focused-versus-full gaps among the models tested. Claude 4 models often abstained when evidence was ambiguous. | The focused inputs were curated to contain the answer evidence. The two conditions measure widely separated points and leave the onset of degradation open. [Chroma Context Rot](https://www.trychroma.com/research/context-rot) |
| Multi-hop graph reasoning, Anthropic (2026) | GraphWalks BFS F1 from the 256K to the 1M subset was **85.9 to 68.1** for Opus 4.8, **76.9 to 40.3** for Opus 4.7, and **61.1 to 16.3** for Opus 4.6. | The decline varies by model. The longer subset was run on an internal setup because the problems exceed the public API’s 1M limit. Long prompts become harder to use when a model must identify a relevant fact among similar or conflicting details, or join evidence across several locations. *Lost in the Middle* found that the position of relevant material can change performance, with many tested models using evidence more reliably near the beginning or end. RULER found that strong results on simple retrieval could coexist with sizeable declines on multi-hop tracing, aggregation, and question answering. Those studies help explain why a successful exact-string lookup says little about whether an agent will still obey an earlier user correction while modifying code. [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/), [RULER](https://arxiv.org/abs/2404.06654)

Removing the wrong material can make a short context worse. In a 2026 preprint, cutting to 25% of a BABILong prompt lowered Sonnet 4.6’s score by **17.5 percentage points** when the middle was cut mechanically and increased the score by **10.4 points** when the researchers preserved the known answer-bearing information. On MRCR v2, even their signal-aware reduction lowered the same model’s score by **11.2 points**. Real sessions seldom reveal in advance which detail will matter two steps later. Keep the evidence that governs the active task and preserve a way to retrieve details removed from the prompt. [Distractor-Aware Truncation](https://arxiv.org/abs/2608.03297)

## A soft checkpoint gives the active task room to finish

Use the effective window the host exposes, allowing for any earlier host compaction point. The default soft threshold is the smaller of 65% of that window and 160K occupied tokens. That is **130K for a 200K window** and **160K for a fully usable 1M window**. Below the soft threshold, keep working with selective file reads and concise tool results. At the soft threshold, look for a natural break such as a completed investigation, test run, or deliverable phase. A handoff has the most value when substantial work remains and the next phase needs only a subset of the accumulated history. At 85% of the effective window, prioritize preserving a resumable checkpoint before further large context reads. Earlier native compaction can still intervene. [Claude Code’s context management documentation](https://code.claude.com/docs/en/how-claude-code-works), [Anthropic’s context engineering guidance](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

The token cap keeps a move from 200K to 1M from silently pushing the soft threshold from 130K to 650K. A Microsoft preprint covering 13.5 million GitHub Copilot sessions observed compaction trigger clusters near 50%, 65–66%, 80%, and near 100%. Those peaks describe policies in use, so they supply a practical comparison for the default and no estimate of the best Claude threshold. For a profile whose tasks accumulate repetitive logs or earlier discarded approaches, lower the soft threshold or cap and rotate at a phase boundary. For long-document comparison, a cross-file migration, or an investigation where chronology matters, raise or disable the soft cap and mark which sources must stay available together. Keep the hard reserve in that profile. When the host supplies no reliable usage measurement, use phase boundaries or observable repeated context loss as qualitative signals. A token threshold requires a usable counter. [CompactionBench](https://www.preprints.org/manuscript/202611.0780), [Anthropic’s context engineering guidance](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

## A handoff should preserve the next decision

The compact checkpoint needs the latest goal and acceptance criteria, exact user constraints or corrections, current state, decisions still in force, modified artifacts, latest verified tests or findings, and the next concrete action. For failed attempts, retain the failure that changes what to try next and enough evidence to distinguish it from a guess. Longer logs, code bodies, and research notes can stay at their source paths or URLs. When updating a checkpoint, verify changed facts against the current workspace or original evidence. This limits the chance of repeating an old mistake or carrying a mistaken summary into the next session. Anthropic’s long-running agent experiments used durable progress artifacts across clean sessions. Factory’s vendor-run evaluation found that a structured, incrementally updated summary scored 3.70 out of 5 on retrospective probes, compared with 3.44 for Anthropic’s tested method and 3.35 for OpenAI’s. A live continuation test is still needed to establish that a handoff preserves what later work requires. [Anthropic’s long-running agent harness](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents), [Factory’s compression evaluation](https://factory.com/news/evaluating-compression), [TRACE](https://arxiv.org/abs/2608.06503)

Carry forward a previously used skill when its procedure still matters for the next step. Record its identifier and a short reason. A skill that finished its part can leave behind the decision or artifact it produced. This saves reloading its instructions. In the local Claude Code terminal, the Mods integration can save the checkpoint, dispatch native `/clear`, verify the session change, and submit the handoff into the fresh context. The manual `/peakusage:handoff` command writes a Markdown file in the current workspace. The same plugin supplies handoff skills in Claude chat and Cowork, where they create a downloadable Markdown file to attach to a new chat. Claude can select relevant enabled skills in that new chat. [Anthropic on Claude Code Mods](https://claude.com/resources/articles/claude-code-mods), [Claude Code command reference](https://support.claude.com/en/articles/14553413-claude-code-cheatsheet), [Claude plugins](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)

## Measure efficiency per completed task

Fewer retained tokens can still cost more if a reset drops a cache prefix or forces additional tool calls. In a paired ServiceNow test on its own codebase, one Claude Code compressor removed about **8% of input tokens per call**, while the agents took **5–9% more turns** and canceled the expected cost savings. The median Opus run lasted 18 turns, so the result is especially relevant to short tasks. In Microsoft’s CompactionBench tests, monolithic approaches kept about **7–9% prefix-cache hits** on the first call after compaction. The progressive variants kept about **31–33%**. Both results make a case for measuring cold input, cache reads and writes, output, compaction, rereads, and elapsed time separately. [ServiceNow’s Claude Code benchmark](https://www.servicenow.com/community/developer-blog/benchmarking-coding-agents-on-the-now-platform-codebase/ba-p/3617861), [CompactionBench](https://www.preprints.org/manuscript/202611.0780)

To calibrate a profile, repeat the same representative long tasks with native continuation, native compaction, and a Peak Usage handoff at the same point. Hold the starting files, model, effort, and tool access constant. Include a noisy tool-heavy task and a task whose essential evidence spans multiple documents or files. Grade the actual deliverable and the first post-handoff action. Check whether the agent honors the latest constraints, preserves test evidence, returns to the right artifact, and avoids repeating completed actions. Compare total tokens and, where the host exposes them, cost and time per successful task. Keep the earlier trigger when it improves the measured efficiency and passes every critical quality check. If rereads dominate or quality falls, preserve more evidence or move the soft trigger later for that profile. [TRACE](https://arxiv.org/abs/2608.06503), [ServiceNow’s Claude Code benchmark](https://www.servicenow.com/community/developer-blog/benchmarking-coding-agents-on-the-now-platform-codebase/ba-p/3617861)
